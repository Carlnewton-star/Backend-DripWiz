# Roadmap — Backend-DripWiz

*Full-codebase review of `DripWiz254/Backend-DripWiz` as it exists today, grouped by priority. This is a review of the code, not a changelog — see `status.md` for what's actually implemented and working right now.*

## Must-have (blocking / correctness / security)

1. **Rotate every leaked credential.** `config.env` is committed in two places (repo root and `server/config/config.env`) and contains a live `JWT_SECRET`, Cloudinary `CLOUDINARY_API_KEY`/`CLOUDINARY_API_SECRET`, and a `MONGODB_URI`. All of it is in git history, readable by anyone who ever clones the repo.
2. **Stop committing secrets and logs.** There is no `.gitignore` anywhere in the repo. As a direct result, `config.env`, the entire `logs/` folder (including Winston audit JSON files that leak local filesystem paths), and both `node_modules/` trees (9,400+ files) are all committed. Add a `.gitignore`, add `.env.example`, and `git rm --cached` the offending paths.
3. **Fix the app entry point — the server cannot start as committed.** `server/app.js` builds an Express app but never does `module.exports = app`. `server/server.js` does `const app = require('./app')` and then calls `app.set(...)`, which throws `TypeError: app.set is not a function`. This isn't theoretical — the committed `logs/error-2025-04-17.log` shows this exact crash happening on a real run, followed by an `EADDRINUSE` because `app.js` *also* calls `app.listen()` itself, independently of `server.js`'s `http.createServer(app).listen()`. This needs a single, clean entry point.
4. **Fix the global error handler.** `app.js`'s error middleware always returns a hardcoded `500 Server Error`, ignoring `err.statusCode` and `err.message` set by the custom `ErrorResponse` class used throughout every controller. Right now, every intentional 400/401/403/404 thrown anywhere in the API is flattened into a generic 500 by the time it reaches the client.
5. **Fix environment-variable name mismatches.** `server.js` reads `process.env.MONGO_URI`, but `config.env` defines `MONGODB_URI` — the DB connection in `server.js` would receive `undefined`. `controllers/auth.js` reads `process.env.JWT_COOKIE_EXPIRE` for the auth cookie's expiry, but `config.env` defines `COOKIE_EXPIRE` — the cookie's expiry math resolves to `NaN`.
6. **Fix case-sensitive model import paths.** Every controller/middleware/route imports models as `require('../models/User')`, `require('../models/Product')`, etc., but the files on disk are lowercase (`user.js`, `product.js`, `review.js`, `order.js`). This only works today because development happened on a case-insensitive filesystem (Windows/macOS); it will fail outright on any standard case-sensitive Linux deployment target.
7. **Replace all `Document.prototype.remove()` calls.** `controllers/products.js`, `controllers/orders.js`, and `controllers/reviews.js` all call `.remove()` on a fetched document to delete it. That method was removed in Mongoose 7+, and this repo pins Mongoose `^8.13.2` — every delete endpoint will throw `TypeError: ... .remove is not a function`. Use `.deleteOne()` instead. This also silently breaks the cascade-delete-reviews hook in `models/product.js` (`productSchema.pre('remove', ...)`), which will never fire.
8. **Fix `models/user.js`'s missing `crypto` import.** `getResetPasswordToken()` calls `crypto.randomBytes(...)` but the file never `require('crypto')`s it — the forgot-password flow throws a `ReferenceError` the moment it's exercised.
9. **Fix the forgot-password email flow end to end.** `utils/sendEmail.js` exports a `class Email` meant to be instantiated with `new Email(user, url)`, but `controllers/auth.js` calls it as a plain function — `sendEmail({ email, subject, message })` — which is a `TypeError` (a class can't be invoked without `new`). Even if that were fixed, `Email.send()` renders a Pug template from `views/email/*.pug`, and no `views/` directory exists anywhere in the repo. It also calls `htmlToText.fromString(...)`, an API removed in `html-to-text` v9 (the version pinned in `package.json`; the current API is `convert()`). This entire flow needs to be rebuilt, not patched.
10. **Close the registration privilege-escalation hole.** `POST /api/v1/auth/register` reads `role` straight from the request body and passes it into `User.create()`. Any anonymous caller can register as `role: "admin"`. Force `role` to a safe default server-side; only allow role changes through the admin-only user-management endpoints.
11. **Resolve the client submodule / rebuild the frontend.** `client/` is a broken git submodule reference (`160000 commit 6f7c1a2c8...`) with no `.gitmodules` file recording an origin anywhere in the repo's history — the dashboard UI code this repo's README describes is not present and is not recoverable from this repository. Combined with the decision to retire the two prior storefront attempts (`DripWiz-website`, `DripWiz254`), this is the moment to build one clean frontend from scratch rather than trying to resurrect the missing submodule.
12. **Wire up (or remove) product photo uploads.** `uploadProductPhoto` in `controllers/products.js` reads `req.files.file` and `file.tempFilePath`, which is the API shape of the `express-fileupload` middleware — but that middleware is never installed or mounted in `app.js`. `multer` is a listed dependency but is never required or configured anywhere. As committed, this endpoint always fails on `req.files` being undefined.
13. **Verify Express 5 middleware compatibility.** The app pins `express@^5.1.0` alongside `express-mongo-sanitize@^2.2.0` and `xss-clean@^0.1.4`. Both of those packages predate Express 5 and are documented to break on it, because they try to reassign `req.query` in place, which Express 5 made a read-only accessor. This needs to be tested directly and very likely needs a replacement (e.g. a manual sanitize step, or upgrading/swapping these packages).
14. **Reconcile the root vs. `server/` project split.** There are two `package.json` files (root and `server/`) with diverging dependency lists (e.g. `winston-daily-rotate-file` and `html-to-text` only in root; `winston` only in `server/`). The root `package.json`'s `start` script points at a `server.js` that does not exist at the repo root (it's in `server/server.js`), and the README instructs `npm run dev` from the root, but no `dev` script exists in the root `package.json` at all. Pick one project layout and make the scripts match it.

## Nice-to-have (correctness/robustness, not blocking)

- Validate that a product exists (and has enough stock) before `createOrder` builds order line items — right now an invalid `product` id crashes the request with an unhandled `TypeError` instead of a clean 400.
- Add real inventory management: `createOrder` never decrements `Product.stock`.
- Add a request-body validation layer (Joi / express-validator / zod) in front of controllers so malformed payloads fail with clean 400s instead of relying solely on Mongoose schema validation (which frequently surfaces as an unhandled 500 given issue #4 above).
- Remove or finish `middleware/cache.js` — it's dead code (never imported anywhere) and would crash immediately if it were, since the `redis` package it requires is not installed or declared as a dependency anywhere in the repo.
- De-duplicate `server/middleware/async.js` and `server/utils/async.js` — they are byte-for-byte the same file living in two places.
- Consolidate the two `config.env` files into one, and stop them from drifting (root has 11 keys; `server/config/config.env` has only 3).
- Add a real automated test suite — both `package.json` files currently have `"test": "echo \"Error: no test specified\" && exit 1"`.
- Add a health-check endpoint (`/api/v1/health` or similar) for uptime monitoring once a deployment target is chosen.
- Add API documentation (an OpenAPI/Swagger spec or a Postman collection) — useful in general, and essential once a new frontend team (even a team of one) starts building against this API.
- Tune rate limiting per-route rather than one blanket 100-requests/10-minutes limiter across the entire API — auth endpoints likely want a stricter limit than read-only product listing.
- Consider TypeScript for the backend to match the recommended new frontend stack, now that a larger refactor is already on the table (optional — lower priority than shipping a secured, working API).

## Not necessary (right now)

- Socket.io real-time dashboard updates beyond the current stub (`subscribeToDashboard` logs a message and does nothing else) — there's no dashboard UI to receive these yet; revisit once the new frontend exists.
- Automated backups — mentioned in the README as a feature but no backup code, script, or scheduled job exists anywhere in the repo. Not worth building until there's production data worth protecting.
- Redis caching layer — currently unused and non-functional (see above); not worth repairing until there's a demonstrated performance problem to solve.
- Multi-currency / multi-language support — no evidence this was ever scoped beyond the generic README feature list; not worth designing for pre-launch.
- Scrubbing leaked secrets from git history (as opposed to rotating them) — rotation neutralizes the actual risk immediately; history rewriting is destructive, affects any existing clones, and is explicitly the owner's call to make later, not an engineering blocker now.
